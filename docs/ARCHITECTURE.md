# Architecture: из чего должна состоять система

## Governing principle: backprop не нужен нигде — и sleep, и wake работают через локальную релаксацию

Первая версия этого документа предлагала компромисс "backprop запрещён в
wake, разрешён в sleep". Это была преждевременная капитуляция — есть
доказанная теория, что backprop не нужен вообще, ни там, ни там:

- **Whittington & Bogacz, 2017** (*Neural Computation*, "An Approximation
  of the Error Backpropagation Algorithm in a Predictive Coding Network
  with Local Hebbian Synaptic Plasticity") — predictive coding сеть,
  доведённая локальной Хеббовской релаксацией до равновесия, математически
  приближает (а при fixed-prediction assumption — точно воспроизводит)
  градиенты backprop. Ни одного вызова `.backward()`.
- **Equilibrium Propagation** — energy-based модель, ошибка распространяется
  неявно через локальные возмущения на выходном слое, тоже без autograd.
- **Forward-Forward (Hinton)** — два forward-прохода (positive/negative),
  локальная "goodness"-цель на каждом слое, без backward вообще.

Важно: в архиве `problem3_local_predictive.py` заявлен как "Zero BPTT /
100% Local", но по факту каждый слой вызывает `loss.backward()` +
`torch.optim.Adam` — это НЕ безградиентный механизм, а backprop,
раскреплённый по слоям (нет градиента через время/глубину, но внутри
слоя — обычный autograd). Название переоценивает то, что делает код —
не путать с настоящей Hebbian-релаксацией Whittington & Bogacz.

**Пересмотренный принцип:** wake и sleep используют ОДНО И ТО ЖЕ локальное
правило (Hebbian-предиктивная релаксация к равновесию, без единого
`.backward()` нигде в системе). Разница между ними — не в том, разрешены
ли градиенты, а в **масштабе релаксации**: wake — 1-несколько шагов на
событие, немедленно; sleep — много шагов релаксации по replay-буферу,
медленная интеграция в структурные веса. Один механизм, разный timescale.

Каждый компонент ниже помечен: **[WAKE]** — единичное событие, немедленная
релаксация, или **[SLEEP]** — растянутая релаксация по replay-буферу.
Backprop (`.backward()`/autograd для обучения весов) не используется ни
там, ни там — заменяется predictive-coding-релаксацией или эволюцией/
метаградиентом только на внешнем, редко срабатывающем уровне поиска
правил (компонент 7), который сам по себе не часть цикла жизни организма.

## Компоненты системы

### 1. Растущий структурный субстрат — [WAKE, структурная динамика]
Единый "геном" (одна локальная функция на все клетки), рост/апоптоз
из сигнала локального стресса/ошибки предсказания. База: seed_tissue
линия v1 (`spatial_embodied_tissue.py`), переписать чисто.
→ M0, M1 (самонастройка порогов вместо констант).

### 2. Быстрая ассоциативная память (гиппокамп) — [WAKE]
Хеббовская запись `W += beta * outer(err, sdr)` в разреженном (SDR)
пространстве, прямо во время взаимодействия. Уже доказанный механизм.
→ M0 (retention curve на масштабе), M2 (эволюционируемое правило вместо
ручных beta/eta/decay).

### 3. Ночная консолидация (сон) — [SLEEP]
Batch-replay накопленного за день (+ generative replay старых следов
против забывания) переносит память из гиппокампа в структурный субстрат
через ту же predictive-coding-релаксацию, что и wake, но много шагов
подряд по replay-буферу вместо одного шага на событие — без единого
`.backward()`. После — буфер обнуляется. База по идее (не по коду —
там сейчас backprop+Adam, нужно переписать на релаксацию):
`phase3_thalamus_and_sleep.py`, `phase3_generative_replay.py`.
**Открытый вопрос для M0:** сливать ли с компонентом 1 в одну ткань,
или оставлять раздельными подсистемами с чётким протоколом обмена.

### 4. Гомеостатическая самонастройка — [WAKE]
BCM-подобные скользящие пороги роста/апоптоза/пластичности вместо
констант, разбросанных по коду. → M1.

### 5. Мультимодальное заземление через колонки — [WAKE, структура; обучение колонки — SLEEP]
Много идентичных копий компонента 1 (по одной на модальность + внутренние),
консенсус/голосование вместо ручной формулы слияния (Thousand Brains).
Сами колонки однотипные — учатся так же, как и любая другая, разница
только в том, какой сенсорный поток на входе. → M3.

### 6. Предиктивная цель вместо скриптового понимания — [SLEEP на предобучение, WAKE на inference]
Самонадзорное предсказание собственного будущего состояния/скрытой
модальности (JEPA-стиль), но обучается той же predictive-coding-
релаксацией, что и остальная система (много шагов по накопленному
опыту offline), не backprop. Результат — представления, которые
используются во время online-взаимодействия без дальнейшего обучения.
Заменяет `if/elif` intent-парсер. → M4.

### 7. Эволюционируемое/метаобучаемое правило пластичности — [SLEEP, метауровень]
Коэффициенты ABCD Хеббовского правила ищутся внешним offline-циклом —
здесь эволюционные стратегии (CMA-ES/ES) предпочтительнее метаградиента:
они тоже gradient-free по отношению к самому правилу пластичности,
и не требуют autograd через всю историю обучения ради поиска коэффициентов.
Найденное правило используется в компонентах 2/3 без дальнейшего
обучения. → M2.

### 8. Связывание признаков (binding) — [WAKE]
Временно: VSA/circular convolution (уже работает, 97.7% на unseen-парах).
Целевое направление: фазовая синхронизация осцилляторов между колонками
(биологически точнее, ещё не пробовали). → после M3.

## Итоговая картина одного "дня жизни" организма

```
WAKE (часы, online, без backprop):
  сенсорный поток → компонент 5 (колонки) → компонент 1 (рост/структура)
  → компонент 8 (binding между колонками) → компонент 2 (мгновенная запись
  новых фактов в гиппокамп) → компонент 4 (самонастройка порогов на лету)
  → компонент 6 (readout через представления, выученные заранее во сне)

SLEEP (растянутая релаксация по replay-буферу, тот же механизм что wake,
       просто много шагов вместо одного — ни здесь, ни там нет backprop):
  компонент 3 (replay гиппокампа + генеративный replay старого →
  консолидация в структурный субстрат через predictive-coding-релаксацию)
  → компонент 6 (дообучение предиктивной цели на новом опыте дня, та же
  релаксация) → компонент 7 (редко, не каждую ночь: эволюционный поиск
  коэффициентов правила пластичности, если текущее правило работает плохо)
  → гиппокамп обнуляется, цикл повторяется
```

Это и есть ответ на "нормальная память без проблем LLM": память живёт
не в одном монолитном наборе весов, а в двух связанных, но разных по
масштабу местах — быстрой online-адресуемой (гиппокамп) и медленной
структурной (субстрат), с явным протоколом переноса между ними (сон).
Оба места учатся одним и тем же локальным механизмом (Hebbian-предиктивная
релаксация), без единого `.backward()` в цикле жизни организма — в отличие
от LLM, который пытается закрыть обе роли одним механизмом (backprop через
всю сеть на каждый шаг) и поэтому не может делать ни то, ни другое honestly
online.
