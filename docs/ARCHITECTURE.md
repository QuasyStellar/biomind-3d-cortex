# Architecture: из чего должна состоять система

## Governing principle: backprop не нужен нигде — и sleep, и wake работают через локальную релаксацию

Первая версия этого документа предлагала компромисс "backprop запрещён в
wake, разрешён в sleep". Это была преждевременная капитуляция — есть
доказанная теория, что backprop не нужен вообще, ни там, ни там:

- **Whittington & Bogacz, 2017** (*Neural Computation*, "An Approximation
  of the Error Backpropagation Algorithm in a Predictive Coding Network
  with Local Hebbian Synaptic Plasticity") — predictive coding сеть,
  доведённая локальной Хеббовской релаксацией до равновесия, математически
  приближает (а при fixed-prediction assumption — точно воспроизводит)
  градиенты backprop. Ни одного вызова `.backward()`.
- **Equilibrium Propagation** — energy-based модель, ошибка распространяется
  неявно через локальные возмущения на выходном слое, тоже без autograd.
- **Forward-Forward (Hinton)** — два forward-прохода (positive/negative),
  локальная "goodness"-цель на каждом слое, без backward вообще.

Важно: в архиве `problem3_local_predictive.py` заявлен как "Zero BPTT /
100% Local", но по факту каждый слой вызывает `loss.backward()` +
`torch.optim.Adam` — это НЕ безградиентный механизм, а backprop,
раскреплённый по слоям (нет градиента через время/глубину, но внутри
слоя — обычный autograd). Название переоценивает то, что делает код —
не путать с настоящей Hebbian-релаксацией Whittington & Bogacz.

**Пересмотренный принцип:** wake и sleep используют ОДНО И ТО ЖЕ локальное
правило (Hebbian-предиктивная релаксация к равновесию, без единого
`.backward()` нигде в системе). Разница между ними — не в том, разрешены
ли градиенты, а в **масштабе релаксации**: wake — 1-несколько шагов на
событие, немедленно; sleep — много шагов релаксации по replay-буферу,
медленная интеграция в структурные веса. Один механизм, разный timescale.

Каждый компонент ниже помечен: **[WAKE]** — единичное событие, немедленная
релаксация, или **[SLEEP]** — растянутая релаксация по replay-буферу.
Backprop (`.backward()`/autograd для обучения весов) не используется ни
там, ни там — заменяется predictive-coding-релаксацией или эволюцией/
метаградиентом только на внешнем, редко срабатывающем уровне поиска
правил (компонент 7), который сам по себе не часть цикла жизни организма.

### Экспериментально подтверждено (первая проверка с нуля, `core/predictive_coding.py`)

3-классовая спираль (нелинейная, требует credit assignment через 2 скрытых
слоя), архитектура 2→32→32→3, идентичная для обеих сетей, идентичный MSE
loss, 300 шагов обучения на обеих:

| | Test accuracy | Время (300 эпох) |
|---|---|---|
| PC, zero `.backward()`, Adam на локальном градиенте | 91.1% | 5.9с |
| Backprop, та же архитектура/loss/бюджет | 98.9% | 0.4с |

Энергия релаксации сходится (0.365 → 0.0014) — механизм не расходится и
не буксует. Разрыв в качестве (7.8 п.п.) заметно сократился после замены
голого SGD на Adam поверх локального градиента (было 50 п.п. на первой,
непроверенной попытке — урок из M(-1): не делать вывод по первому прогону
без настройки). Честная цена — PC ~15x медленнее по wall-clock из-за шагов
релаксации, нужно отслеживать по оси "энергия/вычисление" из ROADMAP.

**Статус:** governing principle прошёл первую реальную проверку — работает,
не идеально совпадает с backprop, но сопоставимо на маленькой задаче.
Не доказательство для реальной компетенции (M0+), но снимает риск, что
вся архитектура построена на нерабочем фундаменте.

## Компоненты системы

Статус на конец сессии 2026-09-01: ✅ проверено с нуля, 🔗 слито в
`core/unified_organism.py`, ⬜ ещё отдельный файл, не слит, 🔴 провалено.

### 1. Растущий структурный субстрат — [WAKE, структурная динамика] ✅🔗
Единый "геном" (одна локальная функция на все клетки), рост/апоптоз
из сигнала локального стресса/ошибки предсказания. Реализовано с нуля
в `core/growing_tissue.py` (✅ +33.3 п.п. регенерация), слито в
`core/unified_organism.py` вместе с компонентом 2. Геном теперь РЕАЛЬНО
обучается через PC-релаксацию (было открытым вопросом — решено).
Добавлено сверх исходного плана: **локальное "воспаление"** — временная
пространственная сенсибилизация порога роста вокруг свежей раны, решает
trade-off "стабильность роста vs способность регенерировать" (см.
VERIFICATION_LOG). Масштаб слитой версии: 15-26 клеток, не проверено выше.

### 2. Быстрая ассоциативная память (гиппокамп) — [WAKE] ✅🔗
Хеббовская запись `W += beta * outer(err, sdr)` в разреженном (SDR)
пространстве. Проверено с нуля в `core/sdr_hippocampus.py` — но с важной
поправкой к исходному плану: retention НЕ держится ровно с масштабом,
падает 100%→18% при N=50→4000 (dim=1024), ёмкость растёт с sdr_dim
предсказуемо. В `unified_organism.py` добавлена запись **с приоритетом
по силе метки** (synaptic tagging and capture, Redondo & Morris) - не
было в исходном плане компонента, добавлено по ходу работы, сильный эффект.

### 3. Ночная консолидация (сон) — [SLEEP] ✅⬜
Пересобрана вокруг реальной нейронауки (Complementary Learning Systems) -
не "кто лучше зубрит список", а обобщение схемы vs запоминание исключений.
См. `experiments/sleep_generalization_sanity.py` — кора обобщает (31.2%
против шанса 1.7%), гиппокамп неожиданно тоже частично обобщает через
геометрическую близость SDR-кодов (самостоятельная находка). **Не слито**
с компонентом 1 в единый организм — остаётся отдельным экспериментом.

### 4. Гомеостатическая самонастройка — [WAKE] ✅🔗
BCM-подобные скользящие пороги в `core/growing_tissue.py` (`homeostatic=True`)
для апоптоза - эффект скромнее ожидаемого, `tanh`-нелинейность тканей уже
даёт большую часть устойчивости, BCM добавляет точечную подстройку на
экстремумах (3 порядка величины), не революцию.

**Порог РОСТА в `unified_organism.py` теперь тоже самонастраивающийся** -
не через per-cell EMA (bootstrap-проблема новорождённых), а через
**percentile растущего распределения** ошибки среди живых клеток прямо
сейчас (85-й процентиль, пересчитывается заново на каждой оценке роста).
Прямое A/B сравнение на Colab доказало необходимость: константа 1.7,
откалиброванная локально (24×24), не запускала рост вообще на холсте
28x больше (128×128); percentile-порог, тот же код без изменений,
устойчиво растёт на обоих масштабах (13→17 локально, 13→22 на Colab).

### 5. Мультимодальное заземление через колонки — [WAKE, структура; обучение колонки — SLEEP] ✅⬜
`core/columnar_voting.py` — каждая колонка = независимый `SDRHippocampus`
на свою модальность, консенсус = сумма нормированных сходств. Самый
чистый результат сессии (+27.7 п.п. на K=4 против ручной формулы,
жёстко откалиброванной под 2 модальности). **Не слито** с растущей
тканью — колонки сейчас не растущие, просто параллельные экземпляры памяти.

### 6. Предиктивная цель вместо скриптового понимания — [SLEEP на предобучение, WAKE на inference] ✅⬜
`experiments/jepa_understanding_sanity.py` — самонадзорное предсказание
замаскированного токена, линейный пробник классифицирует held-out
формулировки лучше hardcoded-парсера (100% vs 0% на переставленных
известных словах). Первая версия теста была методологически неверна
(вводила незнакомые слова вместо переставленных известных) - исправлено.
**Не слито** с растущей тканью - работает на bag-of-words векторах текста,
не на пространственной ткани.

### 7. Эволюционируемое/метаобучаемое правило пластичности — [SLEEP, метауровень] 🟡 приостановлено, не закрыто
`core/evolved_hebbian.py` — честный отрицательный результат В ЭТОЙ
КОНКРЕТНОЙ постановке, не приговор идее целиком. После исправления двух
реальных багов (ненормированный D-член, преждевременная сходимость ES)
эволюция достигает fitness, сопоставимого с ручным grid-search на СВОЕЙ
задаче, но **переносится хуже** на новую статистику при обучении на
ОДНОЙ задаче (61.5% vs 73.5% у ручного симметричного правила). Ручное
правило (A=-B, error-correction) остаётся рабочим решением сейчас, в
`unified_organism.py` используется оно — но это не значит, что эволюцию
списали. **Конкретный, ещё не проверенный следующий шаг:** эволюционировать
fitness сразу по распределению задач/масштабов (не по одной A), что и есть
настоящая практика в литературе по метаобучению правил пластичности
(Najarro & Risi оценивают именно так) — наш тест обучал только на одной
задаче, и это могло быть причиной плохого переноса, а не эволюция
как метод. Возвращаться к этому стоит после того, как появится больше
разнообразных задач для честной multi-task эволюции.

### 8. Связывание признаков (binding) — [WAKE] ✅⬜
VSA/circular convolution в `core/vsa_binding.py` — ёмкостная кривая
построена (K=1..512), не "решено": 99.8% на K=32, 10.1% на K=512.
Целевое направление (фазовая синхронизация осцилляторов) **так и не
попробовано** — единственный из 8 пунктов исходного плана, для которого
нет вообще никакой реализации, только план.

## Итоговая картина одного "дня жизни" организма

```
WAKE (часы, online, без backprop):
  сенсорный поток → компонент 5 (колонки) → компонент 1 (рост/структура)
  → компонент 8 (binding между колонками) → компонент 2 (мгновенная запись
  новых фактов в гиппокамп) → компонент 4 (самонастройка порогов на лету)
  → компонент 6 (readout через представления, выученные заранее во сне)

SLEEP (растянутая релаксация по replay-буферу, тот же механизм что wake,
       просто много шагов вместо одного — ни здесь, ни там нет backprop):
  компонент 3 (replay гиппокампа + генеративный replay старого →
  консолидация в структурный субстрат через predictive-coding-релаксацию)
  → компонент 6 (дообучение предиктивной цели на новом опыте дня, та же
  релаксация) → компонент 7 (редко, не каждую ночь: эволюционный поиск
  коэффициентов правила пластичности, если текущее правило работает плохо)
  → гиппокамп обнуляется, цикл повторяется
```

Это и есть ответ на "нормальная память без проблем LLM": память живёт
не в одном монолитном наборе весов, а в двух связанных, но разных по
масштабу местах — быстрой online-адресуемой (гиппокамп) и медленной
структурной (субстрат), с явным протоколом переноса между ними (сон).
Оба места учатся одним и тем же локальным механизмом (Hebbian-предиктивная
релаксация), без единого `.backward()` в цикле жизни организма — в отличие
от LLM, который пытается закрыть обе роли одним механизмом (backprop через
всю сеть на каждый шаг) и поэтому не может делать ни то, ни другое honestly
online.
